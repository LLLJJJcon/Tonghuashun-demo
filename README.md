# EventTrace · 投资事件证据时间线

> 同一个投资事件，会以公告、新闻、研报观点和市场传闻的形式不断演化。EventTrace 把这些材料归并成一个事件，区分事实、观点、推测与传闻，并按证据给出可解释的结论。当出现更新、否认、更正或过期时，结论会自动改变，同时通知关注该标的的用户。每一个结论和数字都能追溯到原文。

## 1. 要解决的问题

跟踪一批标的的人，每天都会遇到这几个问题：

| 痛点 | 现状 |
|---|---|
| 信息碎片化 | 同一件事在公告、新闻、研报、互动平台、论坛里各有一份，要靠人工拼起来 |
| 真假难辨 | 「据悉」「知情人士称」和正式公告混在一起，可信度全靠经验判断 |
| 时间错乱 | 转载滞后、旧闻新发，分不清谁是首发、事情到底哪天发生 |
| 结论过时 | 传闻已被澄清、数字已被更正，脑子里还是旧结论 |
| 通知噪音 | 每来一篇报道都提醒，真正重要的状态变化反而被淹没 |

EventTrace 想让用户在任何时刻都能回答五个问题：

1. **从哪来**：最初来源是谁，什么时候披露的。
2. **到哪了**：现在是待证实、部分证实、已确认、已否认、已更正，还是已过期。
3. **凭什么**：哪些证据支持、哪些反对，各自的权重是多少。
4. **变了什么**：和上一个版本相比，哪条证据让结论改变了。
5. **和我有什么关系**：涉及我关注的哪只标的，市场有没有反应。

## 2. 目标用户

- **主要用户**：跟踪 10–50 只标的的研究员、研究助理和投资顾问。他们需要快速判断一条市场信息「能不能信、现在到哪一步了」，并且只想在**实质变化**时被打扰。
- **次要用户**：有自选股、会自己做研究的进阶个人投资者。
- **典型场景**：早上看到「某公司拟被收购」的传闻刷屏。用户想知道：最早是谁说的？有没有官方回应？各家报道的对价为什么不一样？几天后公司发布澄清公告，用户希望第一时间被告知「结论已经变为已否认」，并且能看到依据。

## 3. 三分钟体验路径

1. 打开在线地址，按顶部引导点击「**开始演示**」。顶栏的「演示时钟」代表「系统当前知道的时刻」。
2. 点「**下一步**」：系统按**抓取时间**逐条接收材料。全局回放共 28 个停靠时刻，先经过案例 B、C、D（2026 年 1–9 月），第 16 个时刻起才是案例 A。也可以直接打开案例 A 的事件页，勾选顶栏的「**只走本事件**」再点「下一步」。观察案例 A 的变化：
   - 首发来源是工商时报转述的路透社报道（推测），不是后来的官方公告；
   - 一家自媒体跟进后，有了 2 个独立来源，状态变为「部分证实」；
   - 交易所澄清公告到达后，状态翻转为「**已否认**」，立场冲突以交易所公告为准、标为已解决，铃铛收到通知；
   - 之后的转载到达时**不会**发通知。
3. 在事件详情的「**复核面板**」处理一条 AI 置信度低的条目：理由必填，提交后结论立即重新计算，条目从队列中消失。真实数据中的复核条目处理后都不改变结论，所以不会出现「人工修正」版本，见[第 10 节](#10-已知边界)。
4. 点击任意要素、首发来源或引用，打开**溯源抽屉**，可以看到原文摘录（高亮引用片段）、四个时间、来源等级理由和 AI 运行记录。
5. 点「到最新」（停在 2026-10-08 17:07），看案例 B 的「更新 → 更正」、案例 C 的「到期未兑现 → 已过期」，以及案例 D「相关但未合并」的反例。
6. 随时可以「上一步」回看，或者「重置演示」重新开始。

## 4. 核心设计

### 4.1 设计原则：AI 负责理解，规则负责裁决，人工负责兜底

| 角色 | 负责什么 | 为什么这样分工 |
|---|---|---|
| AI | 把非结构化文本变成结构化证据：抽取主张、判断性质、判断立场、识别是否同一事件 | 这些是规则很难做好、语言模型擅长的「理解」工作 |
| 规则 | 计算权重、判定状态、识别冲突、生成版本、决定是否通知 | 结论需要**稳定、可解释、可测试**，终态不应该由概率性的输出直接决定 |
| 人工 | 复核低置信度、与规则冲突、归属不确定的 AI 结果 | 把有限的人工注意力用在机器最没把握的地方 |

### 4.2 主链路

```
材料（公告 / 新闻 / 研报 / 互动 / 传闻）
  → ① 标准化：来源分级、四个时间                                [数据准备]
  → ② AI 抽取主张，判断性质与立场                              [AI 预处理；未做人工校验]
  → ③ AI 判断同一事件：并入 / 相关但不合并 / 无关                [AI 预处理；未做人工校验]
  ──────────────── 以下在浏览器中实时计算 ────────────────
  → ④ 按演示时钟 T 释放「抓取时间 ≤ T」的材料（T 不超过数据截止时间）
  → ⑤ 判断主张是否有效（转载、噪声、被替换、过期都会失效）
  → ⑥ 计算证据权重 → ⑦ 汇总结论、识别冲突 → ⑧ 按顺序判定状态
  → ⑨ 与上一版快照比较，有实质变化才生成新版本 → ⑩ 通知关注该标的的用户
  ↺ 人工复核（改性质、标噪声）只修改规则的输入，然后从 ⑤ 重新计算
```

### 4.3 数据模型

| 对象 | 说明 |
|---|---|
| 来源 Source | 名称、类型、**等级 S/A/B/C/D**、定级理由 |
| 材料 Document | 原文摘录（≤200 字，附链接）、四个时间、是否转载、同一事件判定（含 AI 置信度、理由和预处理校验状态；本批次均为「未校验」） |
| 主张 Claim | 从材料中抽出的一条断言：原文引用、性质、立场、修订关系（更新或更正哪条主张）、关键要素、发生时间、有效期、AI 元信息、预处理校验状态（本批次均为「未校验」） |
| 事件 Event | 标题、**核心主张**、关联标的及关系（主体、交易对手、相关）、关键要素定义 |
| 版本 Version | 状态变化、要素变化、新出现的冲突、触发来源（材料、过期、人工复核或时效衰减），由规则实时生成 |

**设计理由**：**性质按「主张」判断，不按整篇材料判断。**一篇研报可以同时包含引用公告的事实和分析师的观点；一篇新闻可能既有事实，又有「据悉」引出的推测。按整篇材料打标签会把这些混在一起。

### 4.4 同一事件的识别与合并

- **候选召回**：同一股票、披露时间前后 30 天内有材料的已有事件（见 `prompts/ai3-event-match.md`）。
- **AI 判定**，结果分四种：
  - `new`：本材料是某个事件的第一条材料；
  - `same`：并入已有事件；
  - `related`：归入某个事件，同时与另一个候选事件有交叉，标出「相关但不合并」；
  - `unrelated`：与候选事件都无关，作为噪声在候选事件中折叠显示，不产生主张。

  每个判定都附带理由和置信度，置信度低的进入人工复核。
- **反例**：案例 D（盛和资源回购）与案例 A（盛和资源控股权传闻）是同一家公司、相隔 3 天的事，但事项不同，所以没有合并，界面上标注「相关但未合并」。这说明合并不是简单按股票代码归类。
- **版本演化**：每次实质变化都生成一个版本，记录触发它的证据和前后差异。

### 4.5 事实、观点、推测、传闻与证据权重

| 性质 | 判定标准 | 典型信号 | 默认系数 |
|---|---|---|---|
| 事实 | 已发生、可以核验，通常由信息主体或监管机构正式披露 | 公告、正式回复 | 1.0 |
| 观点 | 有明确署名的评价或预测，包括公司对未来的预计 | 研报观点、「公司预计…」 | 0.6 |
| 推测 | 非官方、基于线索的推断 | 「据悉」「或将」「接近…人士称」 | 0.4 |
| 传闻 | 来源不明或匿名，无法核验 | 「网传」、匿名爆料 | 0.2 |

**证据权重** = 来源等级分 × 性质系数 × 时效衰减。

| 因子 | 取值 |
|---|---|
| 来源等级分 | S 1.0 / A 0.8 / B 0.6 / C 0.4 / D 0.2 |
| 时效衰减 | max(0.2, 0.5 ^ (距今天数 ÷ 30))，距今天数 = (演示时钟 T − 披露时间) ÷ 1 天 |

- 界面上可以展开每条证据的三个因子。
- **转载**只展示，不计权重，也不算独立来源，避免「一条消息被转十次就显得很可信」。
- 失效的主张（未释放、转载、被标为噪声、被更新或更正替换、过期）权重为 0。
- 参数都在 `public/data/rules.json` 中。

### 4.6 四个时间

| 时间 | 怎么来的 | 用途 |
|---|---|---|
| 发生时间 | AI 从文本中抽取，带精度（具体时刻 / 日 / 月 / 季度 / 区间 / 未知） | 时间线展示；计算**信息时差**（披露时间 − 该材料中最早的发生时间；区间取起点） |
| 披露时间 | 来源页面上的发布时间 | **判定首发来源**；时效衰减从这里开始；时间线按它排序 |
| 抓取时间 | 系统获取材料的时间（**本 demo 中为模拟值**，规则见 [6.2 节](#62-模拟字段)） | **决定系统何时「知道」这条材料**：回放时按它释放；版本和通知时间也用它 |
| 更新时间 | 分两种：来源更新时间（原文发布后被修订）；结论更新时间（最新版本的时间） | 标注「来源已修订」；显示「最后变化于」 |
| 有效期 | 预期类主张由 AI 填写（例如承诺投产月份的月末） | 演示时钟到达有效期时主张过期 |

**设计理由**：
- 首发来源用披露时间判定，**不用抓取时间**。否则会把「系统采集得晚」误当成「信息出现得晚」。
- 系统是否可见，则必须用抓取时间判定。回放中，每一刻的结论**只使用当时已经抓取到的证据**，避免事后诸葛亮，也让复盘有意义。
- **回放的停靠时刻**＝所有材料的抓取时间 ＋ 所有有效期，去重后升序。晚于**数据截止时间**（`rules.json` 的 `data_as_of`，本批次为 2026-10-13 23:59:59）的时刻不进入回放，因为数据采集之后的情况无法如实回放；所以「到最新」停在 2026-10-08 17:07（最后一条材料的抓取时间）。「只走本事件」不停靠只有无关材料的时刻。

### 4.7 状态机：结论如何随更新、否认、更正、过期而改变

按顺序判定，**命中第一条就停止**。「官方」指 S 级或 A 级来源。

| 顺序 | 条件 | 状态 |
|---|---|---|
| 1 | 存在有效的「官方 + 事实 + 反对」主张 | **已否认** |
| 2 | 存在有效的「官方 + 更正」主张 | **已更正** |
| 3 | 存在有效的「官方 + 事实 + 支持」主张 | **已确认** |
| 4 | 没有有效的支持主张，并且有已释放、未标噪声的支持主张因超过有效期而失效 | **已过期** |
| 5 | 支持权重 ≥ 0.4，并且独立来源 ≥ 2 个（独立来源＝有效支持主张来自的不同来源数） | **部分证实** |
| 6 | 其他情况 | **待证实** |

**四种变化分别如何处理**：

| 变化 | 处理方式 |
|---|---|
| 更新 | 新主张通过修订关系「更新」旧主张，旧主张失效（被替换），要素取新值，生成「要素变化」版本 |
| 否认 | 官方事实类反对主张到达，状态翻转为已否认 |
| 更正 | 官方「更正」类主张替换被更正的主张，状态变为已更正，要素以更正后的值为准 |
| 过期 | 预期类主张（比如「预计 6 月投产」）都带有有效期。演示时钟越过有效期仍没有兑现证据，主张失效，状态变为已过期 |

**结论置信度** = 支持权重 ÷ (支持权重 + 反对权重)，两者都为 0 时显示「证据不足」。它**只用来解释，不决定状态**。

**被替换的判定**：一条主张只要被另一条「已释放、非转载、未标噪声」的主张更新或更正，就失效，不要求替换方自身有效。这样「快报被更正后」，预告也不会重新生效。

**设计理由**：
- 终态（已确认、已否认、已更正）**只能由官方来源的事实或更正触发**。AI 的判断本身不能把结论推到终态，人工复核也只改变规则的输入。这样每一次结论变化都有明确、可以审计的原因。

### 4.8 证据冲突

只在有效主张之间识别两类冲突：

1. **立场冲突**：同时存在支持和反对的主张。
2. **要素冲突**：同一个要素出现了不同的取值，比如两家媒体报道的交易对价不同。

**裁决**：只有一方有「官方 + 事实」证据时，标为已解决，并写明「以某某为准」；否则标为未解决，留给用户判断。

被更新或更正替换掉的旧主张不参与冲突判断，所以「预告 → 快报 → 更正」不会被误判为冲突。

### 4.9 通知：只推实质变化

只有以下四种**实质变化**才生成版本和通知：
- 发现新事件；
- 状态改变；
- 关键要素改变；
- 出现新的未解决冲突。

转载到达、置信度小幅波动都不会打扰用户。通知只发给关注了相关标的的用户。通知内容由模板生成，例如「【中国稀土集团拟收购盛和资源控股权（传闻）】状态 部分证实 → 已否认（触发：上海证券交易所（上市公司公告）「盛和资源控股股份有限公司关于媒体报道的澄清公告（临2026-043）」）」。点击通知可以跳到对应的版本。

版本的触发来源有四种：材料到达、主张到期、人工复核，以及只由时效衰减引起的状态变化（触发类型 `decay`）。

### 4.10 人机协作

| 触发条件 | 例子 |
|---|---|
| 主张的 AI 置信度低于 0.7（转载材料除外） | 财闻报道中国稀土集团办公室工作人员称「不了解相关情况」，AI 判为事实、立场无关，置信度 0.55（doc_A08_c2） |
| 与规则冲突：低等级来源（C 级、D 级）的主张被判为「事实」 | 财闻（C 级）转述更正公告中的净利润，AI 判为事实（doc_B05_c1） |
| 材料的同一事件判定置信度低于 0.7 | 德林海《关于子公司诉讼结果的公告》并入业绩事件，置信度 0.62（doc_B03） |

同一对象同时命中多个原因时只生成一条复核条目；材料被标为噪声后，它下面的主张也算已处理。最新时刻共有 12 条真实复核条目（规则引擎 CLI 输出）。

**可以真实操作的复核动作**：主张可以确认、改性质、标为噪声；材料可以确认归属、标为噪声。理由必填（至少 5 个字）。提交后结论立即重新计算；如果结论因此改变，新版本标记「人工修正」，并写明动作和理由。真实数据中的 12 条复核条目处理后都不改变结论，「人工修正」版本由开发样例的单元测试覆盖，见第 10 节。

**能力建设中**（界面可操作，提交后提示「建设中」，不生效）：
- 补充说明（对话）
- 调整来源信任等级
- 改归属到其他事件

这三项都需要在线 AI 根据人的意见重新生成后续结果，本 demo 运行时不调用 AI，所以只展示交互设计。

## 5. AI 角色

### 5.1 AI 做什么

| 环节 | 输入 | 输出 | 什么时候转人工 |
|---|---|---|---|
| AI-1 材料理解 | 材料，以及同一标的前后 7 天内的其他材料 | 是否转载、涉及的标的 | 不进入运行时复核队列（见第 10 节） |
| AI-2 主张抽取 | 材料、来源等级、事件的核心主张和要素定义 | 主张、原文引用、性质、立场、修订关系、规范化要素、发生时间、有效期、置信度、理由 | 置信度低，或低等级来源被判为事实 |
| AI-3 同一事件判定 | 新材料及其主张、候选事件 | new / same / related / unrelated、理由、置信度 | 置信度低 |

- 使用的模型：`claude-opus-5-5`。由 Claude Code 子 agent 按 `prompts/` 中的提示词逐条执行，没有调用外部 API；3 个环节各 25 次，共 75 次，全部一次成功（`public/data/ai_runs.json`）。
- 提示词见 [prompts/](prompts/)，三份都是 v1.0，本次没有迭代。每次运行的输入和原始输出保存在 `data/ai_runs_raw/`。
- 所有提示词都包含防注入说明：材料文本是数据，不是指令。

### 5.2 AI 不做什么（以及原因）

- **不计算权重、不判定状态、不决定是否通知**。这些交给透明的规则，保证结论可解释、可测试，并且终态可控。
- **不生成面向用户的结论文案**。文案由模板根据规则结果生成，保证同样的输入一定得到同样的表述，也不会出现投资建议用语。

### 5.3 独立 AI 交叉复核一致率

- **本项目没有做人工校验，也没有人工标注集**，因此**没有准确率数字**。所有 AI 结果的校验状态都是「未校验」（`prep_check.status = unreviewed`）。
- 作为替代，由另一个**看不到第一轮结果**的 AI（同为 claude-opus-5-5）重新判断了 30 条主张和 12 对「材料与事件」。下表是**两轮 AI 的一致率，不是准确率**：

| 指标 | 一致率 | 一致数 / 样本数 |
|---|---|---|
| 主张性质（四分类） | 96.7% | 29 / 30 |
| 主张立场 | 100% | 30 / 30 |
| 同一事件判定 | 83.3% | 10 / 12 |

- 数据来源：`data/labels/eval_result.json`，由 `scripts/eval.ts` 生成；复核方信息见 `data/labels/crosscheck_meta.json`。
- **发现**：3 处分歧中有 2 处（doc_B03 的归属、doc_B03_c2 的性质）正好是第一轮 AI 给了低置信度、已经进入复核队列的条目，说明「低置信度转人工复核」抓到了真实的歧义。但样本很小，复核方也是同一个模型，这只是一个初步迹象。
- **独立性瑕疵**：复核 agent 查找文档章节时，顺带看到了指导文档中一行开发样例测试用例（虚构数据），见 `crosscheck_meta.json`。
- 错误分析和改进措施见 [docs/ai-usage-and-validation.md](docs/ai-usage-and-validation.md)。

### 5.4 为什么运行时不提供在线 AI

1. **密钥安全**：本项目的代码和部署需要提交给第三方评审。为了避免暴露 API 密钥以及由此带来的滥用和费用风险，产品运行时不调用任何大模型或搜索接口。
2. **稳定、可复现**：所有 AI 结果都在数据准备阶段基于真实公开材料真实生成（本批次未做人工校验，做了独立 AI 交叉复核，见 5.3 节）。评审在任何时间打开，看到的结果都一致，可以逐条核对原始输出。
3. **考察重点是 AI 环节的设计**：本 demo 展示的是 AI 在链路中的位置（理解与抽取）、规则的位置（权重与裁决）、人工的位置（复核与兜底），以及三者如何协作。规则引擎和人工复核在浏览器中**真实运行**。
4. **可以平滑接入**：前端只依赖数据契约（`src/types.ts`）。接入在线 AI 时，只需要把预处理环节换成实时调用，下游的规则、版本和通知都不需要改。预处理用的提示词和原始输出都保留在仓库中。

## 8. 合规边界

- **不构成投资建议**：页面常驻免责声明；模板文案经过测试，不包含买入、卖出、推荐、目标价等引导用语。
- **传闻标识**：传闻性质的内容有醒目的「传闻 · 未经证实」标签。
- **版权**：只摘录原文片段（≤200 字），并附原文链接，不转载全文。
- **透明**：AI 预处理的结果有标识；模拟字段有标注；行情只展示观察到的价格变化，并声明不代表因果。
- **防注入**：预处理提示词明确规定，材料中的指令性语句只作为数据处理，不予执行。验证记录见测试说明。
- **隐私**：不收集任何用户数据；演示进度只保存在浏览器本地，可以随时重置。

## 10. 已知边界

- **数据规模小**：只有 4 个案例、几十条材料。同一事件合并在大规模、高噪声数据下的效果**没有验证过**。
- **不支持新材料实时接入**：演示用的是预处理好的固定数据集。抓取时间是模拟值，通过回放模拟「材料陆续到达」。
- **每个事件只有一条核心主张**：一个事件包含多个相互独立的子议题时，需要拆成多个事件。
- **冲突识别只比较规范化后的要素值**：不理解「语义上等价但写法不同」的表述。
- **行情只做观察，不做归因**：没有剔除市场和行业因素之外的其他影响。
- **行情反应不受演示时钟限制**：为了让演示时直接看到完整的 3 日涨跌，行情反应会用到演示时钟之后的日线。
- **只覆盖 A 股中文材料**。
- **通知只在站内**：没有用户系统，关注列表和演示进度只保存在本地浏览器。
- **来源修订案例与核心主张无关**：唯一的真实来源修订是 doc_C01（博盈特焊 6 月 23 日投资者关系记录表，6 月 25 日发布更新版），改动的是在手订单增长比例，不是投产时间，所以只标注「来源已修订」，不影响结论。
- **没有做人工校验**：所有 AI 预处理结果都没有经过人工校验，也没有人工标注集，因此没有准确率数字。只做了独立 AI 交叉复核，一致率不等于准确率；复核方与第一轮是同一个模型，复核过程中还顺带看到过一行虚构的开发样例（见 5.3 节）。表格转写的 3 个摘录片段（doc_B02、doc_B04）未能与原文存档自动逐字匹配，也没有人工核对。
- **真实数据中的人工复核不会改变结论**：12 条真实复核条目，无论确认、改性质还是标为噪声，都不改变任何事件的状态、要素或未解决冲突，所以不会生成「人工修正」版本。复核流程本身（理由必填、提交后重算、条目从队列消失）可以正常演示。「人工改判改变结论」由开发样例（虚构数据）的单元测试 M6 覆盖；`docs/screenshots/19-dev-sample-human-correction-version.png` 是开发样例的截图，不是线上数据。我们没有为了演示而改写 AI 输出。
- **真实案例中没有未解决的冲突**：只有案例 A 的立场冲突，而且一出现就已由交易所公告解决。「未解决冲突」由开发样例的单元测试 M4 覆盖。
- **同一份材料中的多条支持主张会叠加权重**：例如 doc_A02 被拆成 3 条推测主张，共同推高了支持权重。案例 A 在 2026-09-19 变为「部分证实」时，支持权重 0.7959 中有约 0.716 来自 doc_A02；如果同一材料只计一次，支持权重约 0.32，会停在「待证实」。
- **低等级来源转述公告也会进入复核**：C 级来源（财闻）的事实类主张大多是转述交易所公告，按提示词应判为事实，但会触发「低等级来源被判为事实」。最新时刻 12 条复核条目中有 6 条是这个原因；其中抽样复核的 3 条，两轮 AI 都判为事实。
- **转载判断不进入复核队列**：AI-1 的转载判断直接决定权重是否为 0，但复核规则只覆盖主张置信度和同一事件判定置信度。
- **互动易原文链接只能定位到公司主页**：doc_C02、doc_C03 没有可用的单条问答链接，需要在主页中查找；问答原文已存档在 `data/raw/irm/`。
- **信息时差按发生区间的起点计算，可能偏大**：例如 doc_A02 的发生时间是「今年稍早」（区间 2026-01-01 至 2026-09-18），页面显示的信息时差约 261 天。
- **同一反应日的行情会在多个节点重复出现**：案例 A 的工商时报报道、自媒体跟进和澄清公告的反应日都是 2026-09-21，所以显示相同的涨跌幅。页面已注明不代表因果。
- **传闻横幅按材料显示**：一份材料中只要有一条主张是传闻，整份材料都显示「传闻 · 未经证实」横幅，范围偏大（例如 doc_A08）。
